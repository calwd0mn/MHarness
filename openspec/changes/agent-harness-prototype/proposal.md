# Proposal

## Why

项目已完成初版基础设施、会话接口与 SQLite 存储，尚未接入模型循环。下一步对齐 DSH 的 Session 设计，以数据库替换文件持久化后端，将事件日志、模型历史派生、写入所有权和崩溃修复作为模型与工具闭环的共同基础。

## What Changes

- 使用 React/Vite 前端和 Fastify 后端。启动时固定装配普通 TypeScript 核心模块，Fastify 负责 HTTP 与 SSE。
- 移除中央 `packages/protocol`，由业务模块拥有契约。Session 模块维护自身 HTTP 请求、响应、公开记录和 SSE 业务帧，提供浏览器可用的契约入口及独立服务端入口。内部事件、持久化接口和实现专有类型由对应能力维护，不从公开记录反向推导；审批等能力遵循相同归属原则，不另建跨业务契约或全局类型包。
- 对齐 DSH 的内存追加日志、不可变事件、surface 历史派生、请求重建、fork、持久化 handle 与崩溃修复语义。模型请求在生成前记录每个 Attempt 的历史截点与配置快照引用。采用轻量事件监听与 emit 通知，启动入口显式装配，不引入 Cordis、serial 或 waterfall。
- 引入独立的 SQLite Session 持久化后端，按会话缓冲和串行写入，通过 `await session.flush()` 提供持久化检查点。每库仅运行一个在线后端，取得实例锁后负责写入、修复和实时 SSE，其他进程可读取已提交历史。每会话写入所有权覆盖写 handle 生命周期，修复前先取得所有权。
- **BREAKING**：持久事件序号改为从 0 开始，cursor 表示事件数量和下一事件位置；数据库采用新事件存储格式。旧格式不得静默覆盖或当作新格式打开，既有数据须保留。
- 首个里程碑交付会话创建、纯文本问答、Turn 取消、历史读取和 SSE 恢复。同一会话最多有一个活动 Turn。消息提交可用原 `requestId` 安全重试，协议区分已提交、结果待确认和确认未提交。
- 实时页面首次打开、重连及切回会话均通过 follow 首帧 snapshot 原子替换视图，不额外 GET 首屏历史、不拼接旧草稿。第一版只订阅当前选中会话，快照含完整公开历史；前端以 subscriptionGeneration 隔离旧回调，串行处理帧，异常重连采用退避及次数上限。
- ReActAgent 按会话加载、跨 Turn 复用，由 AgentManager 管理创建与关闭。历史和 SSE 读取不创建 Agent。活动 Turn 期间新消息返回 409，不持久化、不排队。提交消息与 Turn 开始记录确认回滚时丢弃暂存批次，202 表示已持久接受并由后端接管执行。启动修复使用临时写 handle，不创建 Agent 或续跑。
- 通过统一 Model Adapter 驱动有限步数的模型与工具循环，保存实际模型上下文、工具调用、结果和最终回答。
- 纯文本问答闭环验收后，交付独立压缩和 Turn 内压缩的内部调用能力。摘要替换只影响后续模型输入，原聊天历史仍可读取。
- 保留 ReActAgent、工具批次调度器、工具执行服务与独立审批服务的职责划分。工具初期串行；调度器记录 tool/call 与配对结果，tool/call 只表示进入调度，不证明正文执行。Adapter 负责请求序列化、鉴权接入、统一流与错误、请求超时及取消清理，不修改 Session 或自行重试。
- 工具通过 MCP Client 接入，声明副作用类型、幂等支持、结果查询能力、审批策略和超时配置。
- 只读工具默认免审批；有副作用及能力未知的工具默认需审批，允许显式配置覆盖。审批绑定工具、参数和稳定操作标识。
- 建立操作标识与工具端去重合约，用模拟副作用工具验证重复请求、参数冲突和响应丢失路径。
- 本地且保证协作取消后退出的工具，超时后等待退出清理；MCP 和无此保证的工具停止等待，再按副作用与确认事实结算。副作用或未知能力调用无法确认结果时结束本轮，不自动重试。
- 自有工具成功值先校验再派生模型 content 与展示元数据，外部 MCP 允许 content-only 成功。错误、超时、取消及未知结果均保存模型可见 content，执行事实与原因分别表达，只有成功结果能携带批次结束意向。
- 后续计划包括结果核实、迟到结果处理和恢复执行；权限体系、复杂并发、自动重试和进程重启后续跑不在第一版范围。

## Capabilities

### New Capabilities

- `agent-execution`: Session 事件日志、历史派生、fork、存储访问与所有权、持久化检查点、崩溃修复，以及 Turn 生命周期和模型与工具循环。
- `execution-streaming`: 前端流式观察、历史重建和 Turn 状态展示。
- `tool-governance`: 工具能力合约、审批、操作幂等及超时策略。

### Modified Capabilities

无。

## Impact

保留 Node.js 24、pnpm workspace 和本地单机定位，重构现有 SessionStore、协议序号及会话接口装配。SQLite 存储事件与独立 header，查询状态由事件派生；相关文档和测试随重构更新。现有第一阶段完成记录作为旧基线保留，新任务验证新的 Session 设计。Model Adapter、MCP Client、模拟工具服务及既有审批和超时产品规则继续在此基础上实现。

模块迁移涉及 workspace 依赖、包导出、编译配置、路由与前端消费者；`packages/session` 承载会话业务，通过 `@mharness/session/contracts` 和 `@mharness/session/server` 区分浏览器契约与服务端能力。迁移先保持既有行为，再结合 Session 重构切换内部事件与公开映射，最终删除旧包及其依赖。浏览器入口须检查完整运行时和类型依赖链，避免引入服务端资源。契约字段与 HTTP/SSE 行为仍按既有讨论任务确认，目录迁移不代替协议确认或持久格式验收。
