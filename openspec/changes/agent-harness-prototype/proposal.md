# Proposal

## Why

项目已完成初版基础设施、会话接口与 SQLite 存储，尚未接入模型循环。下一步对齐 DSH 的 Session 设计，以数据库替换文件持久化后端，将事件日志、模型历史派生、写入所有权和崩溃修复作为模型与工具闭环的共同基础。

## What Changes

- 使用 React/Vite 前端和 Fastify 后端。启动时固定装配普通 TypeScript 核心模块，Fastify 负责 HTTP 与 SSE。
- 移除中央 `packages/protocol`，由业务模块拥有契约。Session 核心维护事件数据定义，Session API 维护 HTTP 请求、响应及 SSE 传输封装，并提供浏览器契约和服务端能力的独立入口。持久化接口及实现专有类型由对应能力维护，审批等能力采用相同的归属原则。
- 对齐 DSH 的内存追加日志、不可变事件、surface 历史派生、请求重建、fork、持久化 handle 与崩溃修复语义。fork 可以复制父会话尚未落盘的稳定前缀，子会话首次 append 原子提交自己的 header 与初始日志后发布。模型配置由 `request/header` 保存，每次调用从当时的 surface 派生消息，已结算请求按各自 Assistant 结算前的日志重放。采用轻量事件监听与 emit 通知，启动入口显式装配。
- 引入独立的 SQLite Session 持久化后端，按会话缓冲和串行写入，通过 `await session.flush()` 提供持久化检查点。每库仅运行一个在线后端，取得实例锁后负责写入、修复和实时 SSE，其他进程可读取已提交历史。实时 follow 从 live Session 展示已接受的事件，HTTP 持久历史和重启恢复读取已确认前缀。读取无需排空缓冲，模型请求及顶层工具执行仍受持久化检查点约束。每会话写入所有权覆盖写 handle 生命周期，修复前先取得所有权。
- **BREAKING** 持久事件序号从 0 开始，`session.seq` 表示事件数及下一事件位置。HTTP 历史和 SSE 使用原始事件，游标直接指向当前前缀末条事件的 `seq`，空前缀为 -1。Web 从事件派生聊天、工具和审批视图。数据库采用新事件存储格式，既有数据须保留。取消入口改为按会话停止当前任务。
- 首个里程碑交付会话创建、纯文本问答、会话取消、历史读取和 SSE 恢复。同一会话最多有一个活动 Turn。消息以 live Session 受理为准，同一会话内可用原 `requestId` 重发，首次受理内容生效。
- 检查点失败导致 Turn 停止时以通用 Agent 错误通知并记录失败终态。实时页面首次打开、重连及切回会话均通过全量 follow 快照原子替换视图。第一版只订阅当前选中会话，分页后置。前端按订阅代次隔离旧回调并串行处理帧，断线或客户端检测到缺口时有界重连，收到服务端终止错误时保留画面并等待主动重试。
- ReActAgent 按会话加载、跨 Turn 复用，由 AgentManager 管理创建与关闭。历史和 SSE 读取不创建 Agent。`SessionCommandController.prompt()` 先查重再检查 Agent 状态，非空闲时拒绝新编号并返回 `agent_busy`。受理依次追加 Turn 开始、首个 Step 开始和用户消息，由写入器按序缓冲及分批。受理响应确认内存接受，首次模型请求前通过持久化检查点。启动修复使用临时写 handle，不创建 Agent 或续跑。
- 通过 `LlmRuntime` 与 Provider Adapter 的统一内容块流驱动有限步数的模型与工具循环。每次模型请求独立组装 Assistant 内容、保存可重放的紧凑流，并发布实时草稿。工具批次归属发起调用的 Step。保存实际模型上下文、工具调用、结果和最终回答。
- 纯文本问答闭环验收后，交付独立压缩和 Turn 内压缩的内部调用能力。摘要替换只影响后续模型输入，原聊天历史仍可读取。
- 保留 ReActAgent、工具批次调度器、工具执行服务与独立审批服务的职责划分。工具初期串行，调度器记录 `tool/call` 与配对结果。Adapter 负责厂商协议、鉴权、请求超时及取消清理。`LlmRuntime` 选择 Adapter 并将异常归一为终止流事件。会话压缩阶段支持输入上下文超限后在同一 Step 压缩并重试，每个 Turn 最多一次。
- 工具通过 MCP Client 接入，声明副作用类型、幂等支持、结果查询能力、审批策略和超时配置。
- 只读工具默认免审批；有副作用及能力未知的工具默认需审批，允许显式配置覆盖。审批绑定工具、参数和稳定操作标识。
- 建立操作标识与工具端去重合约，用模拟副作用工具验证重复请求、参数冲突和响应丢失路径。
- 本地且保证协作取消后退出的工具，超时后等待退出清理；MCP 和无此保证的工具停止等待，再按副作用与确认事实结算。副作用或未知能力调用无法确认结果时结束本轮，不自动重试。
- 自有工具成功值先校验再派生模型 content 与展示元数据，外部 MCP 允许 content-only 成功。工具结果持久化为可重放的模型消息、可选展示数据与可选错误码，普通事件省略原始业务值。首版用通用失败表达错误、超时和取消，结构化的结果未确认状态留待后续。只有成功结果能携带批次结束意向。
- 前端首轮建立一致的随系统明暗主题、可访问基础控件和会话页面分层，支持安全的基础 Markdown、代码复制、按会话保留编辑草稿与阅读位置，以及通用工具和审批展示。沿用既有 follow 与提交语义，以原始事件夹具和受控 HTTP 替身独立验收；正式工具与审批联调保留在 6.3、6.4。
- 后续计划包括工具结果核实、迟到结果处理、恢复执行、权限体系与复杂并发。

## Capabilities

### New Capabilities

- `agent-execution`: Session 事件日志、历史派生、fork、存储访问与所有权、持久化检查点、崩溃修复，以及 Turn 生命周期和模型与工具循环。
- `execution-streaming`: 前端流式观察、历史重建和 Turn 状态展示，以及主题控件、消息阅读、工具与审批交互。
- `tool-governance`: 工具能力合约、审批、操作幂等及超时策略。

### Modified Capabilities

无。

## Impact

前端改动限定在 `apps/web` 的主题、基础控件、会话控制与功能视图；Markdown 解析依赖在实施计划中核定。首轮不为审批发布第二套公共 Schema，不以替身验收替代服务端实现或正式联调。设计依据见 `docs/superpowers/specs/2026-11-16-frontend-session-experience-design.md`。

保留 Node.js 24、pnpm workspace 和本地单机定位，重构现有 SessionStore、协议序号及会话接口装配。SQLite 存储事件与独立 header，查询状态由事件派生；相关文档和测试随重构更新。现有第一阶段完成记录作为旧基线保留，新任务验证新的 Session 设计。Model Adapter、MCP Client、模拟工具服务及既有审批和超时产品规则继续在此基础上实现。

模块迁移涉及 workspace 依赖、包导出、编译配置、路由与前端消费者。`packages/session` 通过 `@mharness/session/contracts` 和 `@mharness/session/server` 区分浏览器契约与服务端能力。迁移先保持既有行为，再结合 Session 重构切换到原始事件与 HTTP/SSE 封装，最终删除旧包及其依赖。浏览器入口须检查完整运行时和类型依赖链，避免引入服务端资源。协议实现和持久格式由对应实施任务验收。
