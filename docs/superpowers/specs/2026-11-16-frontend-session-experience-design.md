## 目标与依据

在现有 React Web 中建立一致的主题与基础控件，将当前聊天页按职责拆分，并完整展示已有协议中的消息、工具、审批和 Turn 状态。采用“基础与分层先行”的路线，先统一视觉和会话视图，再实现交互；前端使用事件夹具与 HTTP 替身验收，正式后端联调等待任务 3.3 与 3.5。

MHarness 保持 React 19、Vite、普通 TypeScript 固定装配和现有 Session 协议。参考上游 DSH 提交 `39163dd30f703a79079e2d2446545cff3c453738` 的客户端设计；采用源码组织与交互原则，按本项目事件和接口实现。

## 视觉与交互

视觉方向是中性色工作区、低对比度侧栏、少量语义强调色和清晰的文字层级。页面以会话操作和正文为中心，助手正文使用平面排版，用户消息保留独立气泡，工具过程使用紧凑展开行。

主题独立维护表面、文字、边线、强调、错误、阴影、排版、圆角与动效变量。圆角按用途取值：微型细节 4px、紧凑控件 8px、标准控件 12px、分组内容和代码块 16px、消息气泡 20px、主容器 28px。标准按钮使用 H36/R12，保留确实需要的圆形控件例外。组件颜色使用语义变量，功能样式以 CSS Modules 共置；全局样式仅保留基础排版和页面基线。

浅色与深色均检查常态、悬停、按下、聚焦、禁用、进行中和失败。悬停视觉效果限定在支持 hover 的设备；必要操作在触屏上始终可达。控件不通过改变尺寸或圆角表达状态。过渡主要用于按钮、展开与焦点反馈，并遵循减少动态效果偏好。

桌面保留侧栏与会话区；窄屏使用现有导航折叠布局方向，使正文与发送区可达。长参数、代码、工具结果和较长标签分别按内容规则换行或在自身区域滚动。低高度和浏览器缩放场景允许页面滚动，避免输入区或审批操作被固定容器裁掉。

## 前端职责与源码组织

保留 `apps/web/src/App.tsx` 为组装入口，保留 `apps/web/src/session/` 中已有的订阅、目录和提交能力。新模块围绕实际功能组织，不为每项 DSH 包建立对应 workspace。

| 层次 | 职责 | 建议位置 |
| --- | --- | --- |
| 主题与样式基线 | 视觉变量、明暗模式与页面基础规则 | `apps/web/src/theme.css`、`style.css` |
| 通用 UI | 实际被复用的按钮、展开行与状态提示 | `apps/web/src/components/ui/` |
| 会话控制 | 选中会话、订阅生命周期、提交与取消动作、异步结果归属 | `apps/web/src/session/` 中的控制 hook 或适配模块 |
| 会话视图投影 | 由原始事件、实时草稿和本地提交状态派生可渲染数据 | `apps/web/src/session/` 中的纯函数模块 |
| 功能组件 | 导航、消息、输入区、工具与审批的显示和局部交互 | `apps/web/src/features/conversation/` |
| 外部接口适配 | HTTP 请求与响应校验，向组件提供普通异步回调 | 对应前端功能目录；已有接口继续使用公开 Session 入口 |

组件只消费数据和动作 props，局部持有展开、复制反馈等展示状态。网络请求和 SSE 订阅不散落到消息或工具卡片中；一份选中会话状态对应一份有效订阅。沿用 `FollowController` 的代次隔离、串行处理、原子快照安装、重连预算和稳定消息节点交接。

视图数据使用判别联合描述消息、工具、审批及状态行。组件专用 props 与组件共置；被多个会话模块使用的视图类型放在拥有该投影的模块中。浏览器使用 `@mharness/session/contracts`，不导入服务端事件接纳索引、SQLite、Node 资源或工具执行实现。

TypeScript 禁止 `any`。本次新增或变更的模块与 API 按 `jsdoc-contracts` 维护中文 JSDoc；内部注释仅解释非显而易见的原因、约束和风险。优先使用维护中的依赖承担 Markdown 解析，不手写完整解析器；具体依赖与版本在实施计划中核定。

## 会话与消息

首屏、切回和重连仍由 follow 首个完整快照建立状态，不增加首屏历史 GET，不拼接旧订阅的草稿。输入受理继续使用现有 `requestId` 与 `inheritedEventCount` 规则，响应或自有消息任一先到均只显示一次。切走会话只释放订阅，取消任务由显式动作触发。

本地编辑草稿按会话隔离，在页面存活期间切换后恢复，刷新后不承诺恢复未发送草稿。待受理提交与普通编辑草稿分别保存；失败、忙碌和网络结果未知继续按既有提交语义处理。更换组件不能造成输入框重挂载、焦点丢失或已输入内容被流式更新覆盖。

用户输入保持文字原貌。助手正文支持段落、标题、列表、引用、链接、行内代码和围栏代码块。原始 HTML 不执行；链接只允许 HTTP(S)、mailto 与页内锚点，其他目标保留为可阅读文字。文件路径暂按文字展示。代码复制保留代码内容并提供成功或失败反馈，首轮不要求复杂语法高亮、数学公式或附件渲染。

流式 Markdown 的未闭合结构可退化为可读文本或代码，不能使整个消息流崩溃。正式消息与活动草稿沿用已有稳定身份，不因每个分片或正式结算重建整条消息。截断、取消、失败和完整结束按记录中的事实区分；失败尝试不凭空生成成功回答。

消息区拥有滚动跟随状态。用户处于底部跟随模式时，新内容保持底部；主动向上阅读后停止强制跟随，并提供返回最新内容的操作。按会话记忆页面存活期间的跟随状态和滚动位置。首轮不新增虚拟列表或历史分页。

## 工具视图

工具调用按当前会话及 `(turn, step, callId)` 关联，`operationId` 连接审批与已校验操作，结果沿消息来源和结果块标识配对。同一个 `callId` 在不同 Step 使用时形成独立视图。快照与实时事件使用同一套纯投影逻辑，组件不自行配对事件。

| 已有事实 | 展示语义 |
| --- | --- |
| 模型参数分片 | 保留在数据层；不执行部分 JSON，也不据此宣告工具已经运行。 |
| `tool/call` | 显示准备调用、工具名与原始参数摘要，可展开原始参数。 |
| `tool/operation` | 显示已校验参数与工具版本，记录操作关联；不把它视为正文已经开始执行的证明。 |
| 活跃 `approval/asked` | 显示等待审批，并关联到确切操作。 |
| 已批准且尚无结果 | 显示等待结果，不能显示执行完成。 |
| 成功 `tool/result` | 展示记录中的模型可见内容与可识别展示信息。 |
| 失败 `tool/result` | 展示记录的安全说明和可用错误码；取消、超时、未开始及结果未确认按可用事实区分。 |

仅含工具声明而无正文的 Assistant 消息不产生空白气泡。工具结果无需等待额外模型回复即可展示，Turn 因工具批次结束时保留已有内容和结果。没有 `tool/call` 的恢复结果按原 Assistant 声明建立未开始视图，保留恢复记录的含义。

通用工具视图始终可用。首轮不建立动态工具 UI 注册框架，不从文本猜测专属工具格式。`meta` 作为工具拥有的 JSON 展示数据处理，不执行其中的 HTML 或代码，不重新调用服务端 `render`，也不把展示数据回写为模型上下文。未知内容块或无法识别的 metadata 使用通用的文字／JSON 展示，保留可检查的信息。

## 审批视图与接口适配

审批详情从 `approval/asked.operationId` 关联 `tool/operation`，显示工具名、定义版本、已校验参数和审批原因。审批 `id` 负责决定配对，不能只凭工具名或参数相同合并请求。首轮仅提供单次允许与拒绝，不加入始终允许或持久权限设置。

视图组件通过普通 props 和异步回调答复，接口适配遵循现有 design §5：`POST /api/sessions/:sessionId/approvals/:approvalId/decision` 接收 `{ outcome: "allowed-once" | "rejected" }`。任务 3.3 尚未提供浏览器共享 Schema，首轮不自行在服务端或公共包发布第二套定义；前端适配先通过受控替身验收，正式接线等待共享契约就绪并统一消费。

| 响应或事件 | 前端处理 |
| --- | --- |
| 请求进行中 | 同一审批的指针与键盘动作共用提交锁，阻止重复答复。 |
| 200 或匹配的 `approval/decided` | 展示已确认决定，迟到响应不重新激活卡片。 |
| 带已有决定的 409 | 按服务端保存的决定收敛，不保持相反的乐观结果。 |
| `409 approval_not_active` | 结束旧交互，说明请求已失效，不伪造审批决定。 |
| 404 | 结束无效请求，提供明确反馈。 |
| 网络结果未知 | 保留待确认反馈；可重试相同审批 id 与决定，后续事件仍可确认结果。 |
| 对应工具结果或 Turn 终态 | 关闭未结算的审批交互，保留已有历史事实。 |

请求回调绑定会话与审批身份。切换会话、审批被替代或组件卸载后，旧回调不能修改另一张卡片或解锁新请求。同步未就绪或失败时，历史内容可读，审批动作等待有效快照恢复后才能启用。客户端决定确认不代表工具已派发或完成。

审批详情获得焦点时，可用 Enter 单次允许、Escape 拒绝；输入框、输入法组合、已消费的事件及原生按钮按键保留自身行为。操作后明确反馈请求状态。所有展开控件和决定按钮具有可访问名称，状态不只靠颜色传达。

## 验收与实施顺序

实现遵循 TDD：先保留并运行现有基线，再为新增行为写能暴露缺陷的测试，然后实现最小改动。实施计划在设计与 OpenSpec 任务均经用户确认、并选择 `continue-dev` 后生成。

建议顺序为主题与实际复用控件、会话控制和页面拆分、消息与阅读体验、工具投影与卡片、审批投影与交互、组装验收。每一步检查现有发送、切换、重连、取消和节点交接，不能以完成样式替换代替行为回归。

| 验收层 | 必须覆盖的代表场景 |
| --- | --- |
| 纯投影 | 快照与增量一致、跨 Step 重用 callId、操作与审批关联、无正文工具消息、成功／失败结果、取消／截断／恢复。 |
| 控件与页面 DOM | 空态与选中会话一致、键盘聚焦、请求锁、迟到回调、审批 200／409／404／网络未知、输入法事件。 |
| Markdown 与阅读 | 不安全 HTML／链接不执行、未闭合代码块可读、复制失败反馈、流式交接节点稳定、向上阅读不被抢滚动。 |
| 受控组装 | 使用现有 Schema 接纳的完整事件窗口和 HTTP 替身驱动真实 App，验证消息、工具、审批及 Turn 状态之间的联动。 |
| 浏览器视觉 | 桌面／窄屏、明暗主题、长文本、低高度与缩放、触屏悬停行为、聚焦与减少动态效果偏好。 |

使用目标仓库实际存在的 Web 测试、类型检查和构建命令；新增测试入口随实施范围明确纳入可执行检查。浏览器验收使用隔离夹具，不连接用户正在使用的数据库或真实副作用工具。现有浏览器自动化曾因环境无法识别当前 URL 停止，后续必须重新检查可用性；若仍受阻，保留未验收项，不用 DOM 测试冒充真实布局或浏览器验收。
