2. **在修复前调用真实 fork。** 构造真实 `AgentManager` 和 `SessionCommandController`，断言父 Agent 未加载，然后 fork，使用缺省锚点。未加载父会话通过只读句柄读取已提交前缀；不要先调用父 `load()` 或启动应用，因为两者会修复父命令。断言子发布后的 `parentSession`、`isSeeded`、`inheritedEventCount = 12`，继承前缀与父快照逐条相等，`session/end-seed` 在 seq 12 且属于子会话；父持久前缀未被 fork 修改。独立只读句柄确认子初始批次已经持久化。
3. **验证子在线恢复和父后续修复。** 捕获子事件、`deriveSurfaceNodes()`、`deriveMessages()` 和替换代数，确认 surface 为 checkpoint 与原助手消息，原用户消息仍在原始事件中。对发布的子 Agent 连续两次调用 `recoverStorage()`，分别比较 live 和持久前缀，断言没有新增事件，也没有继承命令的 `done`。再加载父 Agent，确认其自有命令恰好补一个引用 seq 9 摘要的成功 `done`；重新读取子持久前缀和子视图，确认不受父后续写入影响。
4. **跨关闭和应用启动重开。** 正确关闭 manager、所有句柄和 SQLite；用同一路径创建真实应用并执行 `ready()`，读取子会话 HTTP 原始历史，确认继承边界、完整前缀、seed 标记和无继承 `done`。关闭应用释放实例锁，再以新的 SQLite persistence 和 `AgentManager.load(childId)` 加载子会话，比较事件、surface、消息和替换代数与 fork 时一致；重复在线恢复并核对持久前缀无新增事件。检查父会话成功 `done` 仅存在父历史。确保每个阶段关闭句柄，测试结束删除临时目录。
5. **处理失败而不扩大范围。** 先写断言并运行定向测试；若现有实现已通过，记录这是补足联合验收，不人为制造失败。若暴露实现缺陷，保存失败证据、定位根因并提出必要的最小修复；未获代码修改授权时停止。即使本切片通过，也不勾选 8.4 整项。
