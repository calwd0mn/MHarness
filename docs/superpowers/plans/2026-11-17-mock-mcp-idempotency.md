# MCP 接入与工具端幂等实施计划

基于 main 的 b7f0709，在 codex/mock-mcp-idempotency 的独立工作树实施 agent-harness-prototype 4.1、4.2、4.3。以 tasks.md、design §4.1、§4.2、§6 和 tool-governance 规范为验收依据。

每项由新的 GPT-6.1 Terra / high 开发代理负责，先记录失败测试，再实现并复测。统筹核对任务 diff、实跑验收并记录提交范围，当前项完整通过后才派发下一项。使用 PowerShell 7，TypeScript 禁用 any，按 jsdoc-contracts 维护中文公共契约。测试采用临时库、模拟模型和临时监听地址。

## 4.1 MCP Client 与独立模拟服务

- 使用官方 MCP TypeScript SDK 及本机 Streamable HTTP，优先复用现有 ToolRegistry、操作绑定、批次检查点及结果投影。使用可信配置选择工具和治理，默认启动保持现有行为，配置后可独立启动模拟服务并启用 Harness 接入。
- 使用 Ajv 按远端 JSON Schema 校验，避免强制转换、删字段和补默认值。约定注入工具的顶层 operationId，由 Harness 模型 Schema 与参数边界排除；保留其他输入规则。实际派发从已绑定操作注入标识，并在发送前复验完整载荷，模拟服务在入口独立复验。显式定义保留字段可投影的约束，禁止静默篡改复杂约束。
- 成功 content-only 保存内容并省略 value；运行期保留 structuredContent，持久投影沿用现有契约。出参缺失、不符及协议结构非法返回契约失败；MCP 工具失败保留有效内容，协议及传输故障有独立归类。远程取消沿用现有策略。
- 通过真实 MCP 列表与调用、直打服务入口和 Harness Turn/Session 测试验收，补启动及协议说明。

## 4.2 持久操作台账

- 在模拟服务用独立 SQLite 文件，以 operationId 为唯一键，绑定工具和规范化参数。使用单个事务协调首次执行，原子提交模拟效果与成功结果，重复请求返回已存结果；跨工具和参数冲突保留已有记录。
- 使用临时库通过串行、并发、冲突、重启、异常回滚验收。并发证据应能覆盖共享数据库的独立连接，避免把单进程事件循环串行化当作数据库保证。断言实际效果行数和已存结果。

## 4.3 成功响应丢失与手动重发

- 对指定操作在事务成功确认后注入一次有界故障，在 MCP 传输层丢失响应。故障开关由测试/模拟服务控制，工具参数不承载故障配置。
- 通过真实 MCP 调用确认第一请求响应丢失、效果与结果已提交；重发原 operationId 和原参数获得已有结果且效果总数为一。核对 Harness 调用链无自动重试。

## 最终验证与审查

三项各自验收后运行仓库类型检查、服务端与模拟服务全部测试、Web 测试及构建、Git diff 检查、OpenSpec strict validate。使用已授权的 continue-review，新开三位独立只读审查代理分别检查各任务 diff 和相关集成链路。有证据的问题由开发代理修复，独立审查者复核。记录验收命令、结果、提交和未验证范围。仅更新本批任务，保留 OpenSpec 活跃。
