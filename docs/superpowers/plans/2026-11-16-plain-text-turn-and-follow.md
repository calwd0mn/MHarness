# 纯文本问答与 Session.follow 实施计划

目标是完成 `agent-harness-prototype` 的首个可运行里程碑。使用模拟模型验证会话创建、提交、纯文本回答、按会话取消、已提交历史读取，以及 SSE 首次同步、重连和会话切换。以 OpenSpec 的 `proposal.md`、`design.md` §1–3、§8、`agent-execution` 与 `execution-streaming` 场景及 `tasks.md` 的依赖表为准。工具执行、真实 Provider、fork 正式接线和压缩留在原任务中。

## 验收与 continue-review

1. 相同 `requestId` 的重发，无论 HTTP 响应或 SSE 记录先到，都只产生一条用户消息、一个 Turn 和一次模型请求。新编号忙碌拒绝，不占用编号。
2. 首次模型检查点失败时 Provider 调用为零，用户已受理的事件保留，实时错误和失败终态能被观察，失败后不会越过存储准入。
3. SSE 用全量快照建立原始事件前缀。断线恢复草稿及结算，结算事件和 end 任一先到也只显示一条回答。旧订阅回调不得改变切换后的页面。
4. 实时跟随读取 live Session 的已接受事件，历史 HTTP 读取已提交前缀。验收取消、过程中的重连和关闭释放写入权。
5. 集成树重跑 `pnpm typecheck`、`pnpm --filter @mharness/server test`、Web 新增测试、`pnpm --filter @mharness/web build`、`git diff --check`。仅勾选有完整验收证据的 OpenSpec 任务。
6. 开发与验证后执行用户已指定的 `continue-review`。为各任务 diff 记录独立基线和终点，由新的审查代理对照 OpenSpec 与项目规则检查，问题按文件行号和复现场景报告。修复后复查对应 diff，并重跑受影响验证。
