## 实施边界

- `ReActAgent.prompt` 负责查重、占用、追加 `turn/start → user/message` 和调度驱动。保留查重优先于忙碌与存储准入。受理成功仍为 `202 { accepted: true }`。驱动负责所有 `step/start`、`step/end` 和 `turn/end`。`RunTurn` 的自定义实现也须自行开启所需 Step。在 Step 实际打开前取消或失败时只关闭 Turn。
- `request-context.ts` 将现有准备逻辑分为两个入口。每 Step 使用现有 `LlmRuntime.prepare(config, { recordable: true })` 固定选中的 Adapter、生效路由、生成参数、凭据和超时。用 `snapshotSessionJson` 对完整可记录 header（含 system 和嵌套 tools）做无损校验和复制，校验工具结构后递归冻结，作为本步 hook 和所有业务请求的输入。每次业务请求在 Step 打开后，使用该快照与当前 Session 派生独立消息数组，根据最新 header 和替换代数确定是否追加 header。保持现有重建、可记录参数校验和 `initial / resume / change / series` 语义。配置变化与开始新系列同时发生时保留 `startsSeries: true`。
- 给 `createModelTurnDriver` 增加两个可选的异步回调选项。建议用 `preStep` 接收 Session、turn、预定 step、同一取消信号和只读可记录配置（实际路由、生效参数、system、tools），回调完成后才可开启 Step。建议用 `recoverOverflow` 在已接受失败 Attempt 及已发出对应的实时 end 后接收相同上下文和失败信息，返回是否授权继续当前 Step 的下一次业务请求。通过真实驱动装配替身验收，生产装配省略回调。回调运行业务期间保持 Agent 占用，等待点通过直接 `await` 接线，不用 `Session.emit` 或新增事件类型。业务 Adapter 与凭据留在 `PreparedModel.generate` 的闭包中，传给 hook 的配置不包含凭据。
- 8.5 负责 Session 暂存提交、核对和持久化。8.7 经 `RunTurn / ModelTurnContext` 传递 `ReActAgent.storageOpen` 的即时读取，正式 Agent 每次都提供它，直接调用驱动的旧测试可省略。等待返回后先检查存储门，再写本 Step 边界和准备请求。每次请求显式 `await session.flush()`，并在启动模型前再次检查存储门与取消。恢复回调返回后，重新检查取消和存储门，通过后才可派生重试请求或追加 header。即使 flush 已完成核对，Agent 准入仍关闭时，业务 Adapter 仍不能运行。若未知批次占用下一序号，连 `turn/end` 或 `step/end` 也可能无法追加。沿现有驱动拒绝 → Agent 保持存储阻塞的路径收束，只交付实际接受的事件。暂存核对与后续业务结算交给 8.3。
- 8.8 负责 `apps/server/src/model/` 下的本地模型信息、计量及实际发送消息投影。8.7 复用 `PreparedModel`，保留 `request-context.ts` 中私有 `messages(session)` 的签名、函数体和既有模型导入。8.8 可在该函数体内接入共同投影并添加对应 import。8.7 的 hook 可从本步实际路由取模型信息，无需重读配置或查看历史 header 选路。DeepSeek 正常工具续答继续携带原已结算的 reasoning 与配对结果。
- 8.11 负责真实压力流程及其异常告警后继续语义。8.7 的 pre-step 回调拒绝代表无法继续本 Step，由驱动按取消或安全失败结算。8.6 负责真实输入超限恢复、替换代数门槛和重试限额决策。8.7 仅在明确的 `CONTEXT_WINDOW_EXCEEDED` 上接收替身授权，按 OpenSpec 当前限额在同 Step 消费一次额外业务请求机会。回调未接、拒绝授权或第二次仍超限时按该次业务失败结束，输出截断和其他错误不进入恢复。每个 Step 独立持有机会，工具调用与续答仍按原 Step 预算推进。恢复挂起期间收到取消，或回调拒绝明确的 AbortError 时，本轮以 aborted 收束并保留首次失败结算及已发布的 end。
