## 2. 实现按压力收敛的流程

`@apps/server/src/model/token-meter.ts:54`
`@apps/server/src/model/token-meter.ts:73`
`@apps/server/src/agent/commit-tool-result-pruning.ts:20`

1. 检查当前取消和存储准入，按本步实际设置估算 `inputTokens + outputTokens`。输出预留优先生效上限，缺省使用模型声明。缺窗口或缺输出预算时，经 `checkAutomaticPressure` 告警一次并结束本步压缩。
2. 压力低于 `floor(window × 0.8)` 时直接返回。等于或超过阈值时，对完整当前 surface 一次应用 8.9 修剪并等待存储结论。落盘后重新计量。降到阈值以下时结束，本步摘要调用为零。
3. 仍到阈值时，用 `measureRequestPressure()` 给出的 `tailBudget = floor(window × 0.16)` 交给既有安全前缀选择和单次摘要结算。默认 `compactionRetries = 1` 只在首轮已确认成功且重测仍高压时允许再调用一次。第二次从更新后的 surface 重新选区，每次生成独立 `compactionId`。无安全范围时没有摘要调用。
4. 两轮摘要共用同一个失败分支。结构化失败，以及选区、模型准备、开始记录追加直接抛出的异常，由策略处理。修剪构建或校验直接抛错也走此分支。策略层对压缩失败记录一次安全告警，包括存储故障。保留已锁存的存储原因，按该边界停止本轮。准入开放时检查当前 Turn 信号，未取消才停止本次压缩并回到业务检查点。摘要 Adapter 独立返回 `aborted` 时，以当前 Turn 信号决定是否取消本轮。第二轮失败保留第一轮已持久化的替换。两次确认成功后仍高压也告警并保留结果。每个后续 Step 重新计量，摘要使用既有请求级超时。
5. 将 `beforeSubmit` 与 `onPersistenceError` 一并传给 `commitToolResultPruning()` 所调用的 `commitCompactionBatch()`。前者在写入器确认普通前缀后复查信号，取消 guard 的抛错不报告为存储故障。后者将修剪暂存内部普通前缀检查点拒绝或端口持久化抛错的原值交给本轮 `blockStorage`。修剪批次返回待核对时由已有 `commitCompactionBatch()` 报告。writer 告警关全局门后，驱动仍须锁存本轮原故障。修剪确认回滚且准入开放时按第 4 步告警并回到业务检查点。存储阻塞优先于同时发生的取消。已确认提交的修剪和摘要保留，取消阻止后续调用。两入口共用这段接线。

## 3. 验收

- [ ] 用窗口 100000 且含超过 8192 码点工具结果的同一组策略夹具覆盖压力 79999 和 80000。79999 时修剪提交、`compaction/prune` 和摘要调用均为零。80000 时修剪一次并重测，尾部预算为 16000。另覆盖缺预算告警、实际模型切换，以及 system、tools、reasoning 和输出预留计量。
- [ ] 覆盖修剪后降压、一次摘要后降压、两轮成功仍高压、首轮失败和无安全范围。分别让首次摘要准备抛错、修剪构建抛错、首次成功后第二轮结算失败或准备抛错，断言准入开放且未取消时，告警后仍到达业务检查点。验证摘要 Adapter 独立返回 `aborted`，本轮信号仍开放时也告警并继续。第二轮失败保留第一轮结果。断言调用次数、独立压缩身份和第二轮摘要输入来自更新后的 surface。
- [ ] 用真实 Agent、SessionWriter、临时 SQLite 和受控 Adapter 验收首个 Step 及工具续答的下一 Step。真实替换后，在受控业务 Adapter 一进入时从独立 SQLite 读句柄确认必要前缀已提交。用该持久前缀重放 header、system、tools、生效参数和消息，与 Adapter 实际业务请求逐项核对。已有业务请求时，同配置替换产生 `series`，配置改变且替换产生 `change` 与 `startsSeries: true`。首个请求沿既有 `initial` 或 `resume`。follow 验证摘要无业务草稿，`step/start` 在 pre-step 完成后才出现。
- [ ] 在同一真实 `preStep` 分别注入修剪暂存内部前缀检查点拒绝和修剪事务待核对。两案均断言锁存原故障、零 `step/start`、零摘要调用、零业务调用。同时取消仍按存储故障退出，普通 flush 随后核对成功也不恢复本轮。另覆盖修剪确认回滚、摘要待核对、业务请求前 flush 失败，以及修剪提交前、摘要生成中和首次替换后的取消。验证已提交效果可重放，业务检查点失败后业务 Adapter 为零。
- [ ] 跑新增定向测试、服务端与 Session 全量、Web 流式回归、`pnpm typecheck`、OpenSpec 严格校验和 Git 差异检查。生产装配使用受控传输验收。按各任务实际覆盖记录结果，再更新 8.11 的完成状态。

## 评审重点

工作量集中在本步固定配置的复用、修剪进入端口前的取消 guard，以及压缩异常告警之后的存储准入。建议 8.11 先落共用接入点，仅在生产装配注册自己的 hook。8.6 可用同一约定先写策略和测试，集成时沿用该接入点。
